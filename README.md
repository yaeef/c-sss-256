## Introduction ##

This is a robust implementation of [Shamir's Secret Sharing][shamir] designed for high-security environments. Unlike standard implementations that work with small integers, this version leverages the **OpenSSL** library to handle 512-bit prime fields ($GF(P)$), making it suitable for protecting modern cryptographic keys (like AES-256 or RSA private keys).

The core engine is implemented in C, focusing on mathematical precision and memory safety. By using OpenSSL's `BIGNUM` library, we ensure that the secret reconstruction is resistant to the limitations of standard 64-bit arithmetic.

The idea is simple: a secret string (e.g., a master password or a private key) is divided into a specified number of shares ($n$). You also specify a threshold ($k$). You need at least $k$ shares to reconstruct the secret. Any number of shares less than $k$ provides **zero** information about the secret.


## How is it used? ##

The application is designed as a CLI orchestrator that follows the Unix philosophy, prioritizing secure communication via `stdin` to prevent secrets from being leaked in the command-line history.

### Split (Generating Shares) ###

To divide a secret, pipe it into the program using the `-s` flag. You must specify the total shares (`-n`) and the threshold (`-k`).

    echo "AABBCCDD" | ./sss -s -n 5 -k 3

This will generate 5 files named `share_1.sss` through `share_5.sss`. These files can be distributed among different custodians.

### Recover (Joining Shares) ###

To reconstruct the secret, use the `-r` flag followed by at least $k$ share files.

    ./sss -r share_1.sss share_3.sss share_5.sss > recovered_secret.txt

The recovered secret is output to `stdout`. Using a silent pipeline ensures the secret never touches the disk unencrypted if piped directly into another tool (like a decrypter).


## The Shares ##

Each share is stored in a structured format to ensure integrity during the reading process. A typical `.sss` file looks like this:

```text
.:SSS-KEY:.
1:D4387CF0B5BAD332AC44F396684AF92C...
.:END-SSS-KEY:.
```
* **Header/Footer:** Ensures the file is a valid share generated by this engine.
* **ID:** The $x$ coordinate of the point in the polynomial.
* **Value:** The $y$ coordinate (projection) in Hexadecimal format.

## Security Features ##

This implementation goes beyond basic educational scripts. It was built with several "security-first" decisions:

* **512-bit Finite Field:** We use a **Safe Prime** ($P = 2Q + 1$) to define a field large enough to encapsulate any modern encryption key without risk of collision or overflow.
* **Zeroization:** We use `BN_clear_free` for all sensitive variables. This ensures that the secret and the polynomial coefficients are wiped from RAM before the memory is released, guarding against memory dump attacks.
* **Horner's Method:** Polynomial evaluation is performed using Horner's scheme for better computational efficiency ($O(k)$) and numerical stability.
* **Constant Field:** The prime $P$ is hardcoded as a constant, ensuring that shares generated today will be mathematically compatible with the engine years from now.



## About the Source ##

The project is structured for modularity and academic documentation:

* `field.c/h`: Pure Galois Field arithmetic abstraction.
* `sss.c/h`: The core Shamir logic (Lagrange & Horner).
* `sssio.c/h`: Secure I/O handling for files and `stdin`.
* `generador.c`: A standalone utility to generate high-entropy random numbers and primes.
